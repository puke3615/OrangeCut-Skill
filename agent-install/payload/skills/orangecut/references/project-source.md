# Inspect and rebuild a project from source

`oc project source --output <file>.oc.yaml` writes the open project as readable YAML: canvas, assets, ordered tracks, clip `at`/`duration` in decimal seconds, caption text and emphases, and component preset origin. This is an intentional projection. Engine-owned data (transforms, compiled DOM/CSS, curves, probe results) and namespaced `extensions` (linked A/V, track origin, and sound links) appear as `@opaque:<digest>` references into the adjacent `.opaque.json` sidecar. Read the YAML to reason about the edit, but never hand-edit the sidecar or deliver the YAML without it. The sidecar preserves invariants such as paired picture and sound. There is no `--sidecar` option to override it during reconstruction.

`oc project create --from-source <file>.oc.yaml --media-root <dir>` always creates a **new** project. The service imports media under `--media-root`, assigns new asset IDs, and applies the structure as one CommandBatch. It never reconciles an existing project or matches its identities. Use `--title` to override the source title.

To validate the round trip, compare the rebuilt project with the original snapshot, not a second export: otherwise the same omission can go unnoticed on both sides. One 46 s round-trip test retained the source ranges of 9 assets, 59 clips, 20 captions, 36 components, and 45 extension blocks, excluding reassigned asset IDs and the built-in asset pool. Use this export/import pair to share an edit, keep a diffable copy in Git, or start a new cut from a template.

The `dev.orangecut.lineage` v1 extension can be restored through `project.lineage.set`; unknown root extensions are rejected. To copy the open version use `project fork`, and to compare versions use `project diff`. See [Agent project operations](agent-operations.md).
