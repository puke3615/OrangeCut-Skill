## 工作流

### 定点读取

`oc timeline inspect --id <clip-or-caption-id> --json` 只读取匹配对象，响应带 revision、精确区间、源区间与音画关联 ID。
可重复 `--id`、`--track-id`；`--text <片段素材名或字幕文字>`、`--kind clip|caption`、`--external-ref <精确引用>` 进一步收窄。
`--from-frame N --to-frame M` 按当前 Sequence 帧率读取半开区间；范围过滤不裁短返回的实体。
默认最多200项，`--limit` 可调至1000，超过时明确失败，不返回貌似完整的前缀。`--full` 才展开匹配实体的完整领域字段。
可用 `oc capabilities --command clip.add --json` 读取单个原始语义命令的准确 schema 和必要定义，不必阅读全命令目录。
这些查询不产生 revision、Event 或 GUI 状态变化；旧的 `timeline snapshot` 保持完整快照契约。

1. 运行 `oc status --json`。一个服务都没在跑时,`oc` 会自己拉起一个 headless 服务再继续——所以批处理不会因为服务崩了就整批作废,下一条命令就把它接回来。这个二进制没有窗口,拉起不会弹出界面。它只在**零个活服务**时发生:服务活着但没开 Project(`PROJECT_NOT_OPEN`)或者活着好几个(`LIVE_SESSION_AMBIGUOUS`)都是另一码事,那时请用户去开 Project 或只保留目标 Project。用户随后打开 OrangeCut 窗口时,GUI **接管**这个 `oc` 拉起的服务而不是另起一个(同一数据根只有一个服务),所以 `status` 里的 `guiOpen` 会在会话中途从 false 变 true,你的命令继续打到同一个服务上;GUI 关掉后它又变回 headless,服务不会消失。仍报 `ORANGECUT_SERVICE_UNAVAILABLE`,说明这台机器上连服务二进制都没找到——装了发行包的用户不该走到这里(bundle 装在哪、被拖到哪都会被找到),所以对用户就是一句「打开 OrangeCut」;`details.searchedForService` 列出翻过的位置。只有开着源码仓库、又还没构建的情况才需要 `ORANGECUT_SERVICE_BINARY` 指路。`SERVICE_AUTOSTART_FAILED` 则是拉起了但没起来,`details.stderr` 带着这一次的日志尾巴。
   - **信封的 `warnings` 里出现 `SERVICE_RESTART_LOOP`,要当回事报给用户。**自动拉起让批处理不会因为服务崩了就整批作废,代价是把崩溃变无声了——每条命令都悄悄把服务接回来,表面一路绿灯。这条告警就是那个出口:24 小时内拉起达 3 次就出现,带 `starts` / `spanSeconds` / `afterUncleanExit`。`afterUncleanExit` 数的是上一个服务没能好好退出的次数(干净退出会自己删掉注册文件),不为零就说明是崩溃而不是正常关闭,该去查服务日志,而不是接着往下跑。它只反映 `oc` 自己拉起的那些;GUI 宿主自己救回来的不在内。要禁掉自动拉起(比如你就是想确认服务在不在),用 `oc --no-autostart <命令>` 或 `ORANGECUT_NO_AUTOSTART=1`。 服务自己也记账:`status.serviceHealth` 里 `uncleanExitsLast24h` 是最近 24 小时"没干净退出就被再次拉起"的次数,`panicsLast24h` 是其中留下 panic 日志的;前者不为零而后者为零,多半是被杀或硬崩,同样该去查日志。
   - 若没有打开的 Project 且用户要求新建,选一个紧凑的 key 并运行 `oc project create --title <title> --idempotency-key <key> --json`。不带画布选项时 Project 以自动画布模式启动:画布(以及帧率恒定时的帧率)取自放上时间线的第一个视觉 clip——用户手里有源素材又没说格式时,这就是正确默认。只有当用户点名了格式才传 `--width <pixels> --height <pixels>`(偶数,16 到 8192)和/或 `--fps <fps>`;`--aspect-ratio 9:16|16:9|1:1` 仍是遗留的预设捷径。响应不确定后,复用完全相同的 key 与模板;OrangeCut 会返回或重开同一个 Project,而不是建出一个重复的。
   - 用 `oc canvas show --json` 读当前画布——它在具体尺寸与帧率之外还报告 `canvasMode`(仍跟随源媒体时为 `auto`,钉死后为 `fixed`)和 `colorGrading`(整条 Sequence 的调色状态,没调色为 null;**`canvas grade` 每次写的是整份调色,不是增量**——想只改一项手动参数,先 show 读回其余的一起传)。任何时候都可以用 `oc canvas set --width <pixels> --height <pixels> [--fps <fps>] --json` 钉死一个显式格式;显式 set 总会把 Sequence 切到 `fixed`,已有 Clip 保持原有时序与变换。用 `oc canvas grade [--preset <id>] [--intensity <0-100>] [--adjust key=percent ...] --json` 给整条 Sequence 一个统一 look(**`--preset` 与 `--adjust` 给其一即可**:只想手调几个参数、不套任何 look 时,直接 `--adjust exposure=8 --adjust saturation=-5`,不需要拿 `--preset <随便一个> --intensity 0` 绕)(adjust 键:exposure contrast highlights shadows whites blacks temperature tint vibrance saturation,各 -100..100;未知的 preset id 会带着有效列表失败),或用 `oc canvas grade --clear --json` 移除;引擎在预览与导出中以完全一致的方式应用调色,带调色的 Sequence 走 classic 导出路线。**最省事的一档是内置风格**:`oc canvas looks --json` 列出目录(17 个引擎预设 + 8 个内置 LUT,各带中文名、一句适用说明和建议强度),`oc canvas grade --look teal-orange [--intensity <0-100>] --json` 一条命令套上——引擎预设走 `preset`,内置 LUT 走已随工程装好的 `asset-bundled-lut-*` 资产,不用导入任何文件;不给 `--intensity` 就用目录里的建议值,`--adjust` 可以继续叠在上面。**要一个完整的 look 而不是十个参数,用 LUT**:`oc canvas grade --lut <绝对路径.cube> [--lut-intensity <0-100>] --json`——3D `.cube` 文件(达芬奇/Premiere/剪映导出的那种,LUT_3D_SIZE 2..64,1D 不收)先作为 Data 资产导入(同一文件第二次直接复用),引擎的着色器在 preset 与 adjust 之后套用;`--lut` 也接受已导入的 `.cube` 资产 id。LUT 可与 `--preset`/`--adjust` 同用。**每次 `canvas grade` 都是整份替换**:重跑时不带 `--lut` 就等于摘掉 LUT。创意型 LUT 假定输入是普通 Rec.709 画面——手机/AI 生成素材直接套;别拿"log 转 709"那种技术型 LUT 来套普通素材,画面会糊成灰的。
   - 要往别人已完成的视频里烧覆盖层,匹配它的形状而不是自己挑一个:`oc project create --title <title> --match <absolute-video-path> --idempotency-key <key> --json` 从源片取画布与精确帧率,因此没有任何缩放或重采样。它应用文件的旋转标记,把 30000/1001 这类分数帧率保持精确,并直接拒绝可变帧率的源——没有单一帧率可匹配,猜一个会让之后每一帧都错位。先用 `oc media probe <absolute-path> --json` 读文件形状,它不需要打开的 Project,报告显示尺寸、帧率以及帧率是否恒定。
   - 在构建原始 CommandBatch 之前,或请求的编辑可能不受支持时,运行 `oc capabilities --json`。把返回的命令目录当作权威;绝不用一次投机的写入去试探支持性。
2. 看 `oc status --json` 的 `openProjects`:恰好一项,后面的命令都隐式打它;多项,先定下要动哪一个——`export ORANGECUT_PROJECT=<id>`(或每条命令带 `--project <id>`,参数可写在子命令后面,优先于环境变量),之后每个信封顶层的 `projectId` 都回显这条命令打到了谁,核对它而不是假设。点名的工程必须开着,否则 `PROJECT_NOT_OPEN` 带 `openProjectIds`。多开时 `oc project current` 按点名的那一个拼摘要。运行 `oc project current --json`;需要规范的时间线状态时再运行 `oc timeline snapshot --json`。把 `tracks` 当作规范存储而非显示顺序:先按每条 Track 唯一的数字 `order` 排序,再推理自上而下的图层或选择 `trackId`。工程大了整包 JSON 很沉:`--tracks <id,id>`/`--kind video,caption`/`--sequence-id` 只留要看的轨,`--no-assets` 丢掉占大头的 assets 数组;被过滤过的输出带 `snapshotFilter` 声明,别把它当完整工程用。
3. 为用户的意图选择一个语义操作:
   - 列出安全的 Asset 元数据:`oc asset list --json`。
   - 导入明确授权的本地文件:`oc asset import <absolute-path>... --json`。import 只进素材库,上时间线是单独一步 add。
   - 把 Asset 放到精确的零基时间线帧:`oc timeline add <asset-id> --at-frame <frame> --json`。只有当用户指明了 Track 才加 `--track-id <id>`;必须在新 Track 上避开重叠时用 `--new-track`。
   - 在精确的时间线帧上 split 一个 Clip:`oc timeline split <clip-id> --at-frame <frame> --json`。OrangeCut 自动把联动的画面/声音对端纳入同一次原子编辑。
   - 把一个 Clip 移到精确起始帧和/或另一条 Track:`oc timeline move <clip-id> [--to-frame <frame>] [--to-track <track-id>] --json`(至少传一个)。这是非 ripple 移动;目标 Track 必须 kind 兼容且该区间空闲。联动的画面/声音保持相对偏移,在各自的 Track 上原子移动,并拒绝对联动对使用 `--to-track`——先 detach。
   - 在精确帧上只 trim 一个 Clip 的一条边:`oc timeline trim <clip-id> --start-frame <frame> --json` 或 `--end-frame <frame>`。绝不同时传两个。联动的画面/声音按精确的源时间映射原子地一起 trim。
   - **录屏 / 任意视频的区域脱敏**：`oc timeline privacy <clip-id> --region-mode inside --no-faces --strength 40 --box x,y,w,h@起-止秒 --json` 模糊矩形内部；`--region-mode outside` 保留矩形并集清晰，模糊其余画面（自动关闭人脸检测）。`--box` 可重复，每区独立 `[起,止)` 源秒区间；保留模式没有区域生效时全幅模糊。GUI：选中视频 → 画面脱敏 → 框选区域脱敏，可拖框、加多个区域、设时段与高斯强度。轻度/适中/强力为 20/40/70，默认 40；CLI 可用 `--strength-preset light|medium|strong` 或 `--strength 1..100`（互斥）。原素材和原声保留，重开可调，一步撤销；页面变化可切开片段分别处理，不自动跟随滚动内容。文件级 `media anonymize` 支持相同参数。纯区域处理保留源 VFR 时间戳。复杂组合先脱敏成新素材再剪。录屏包装位于组件 → 更多工具，当前不优先完善点击效果。
   - **给一个视频 Clip 遮脸**:`oc timeline privacy <clip-id> --json`——**默认就是云朵贴纸**(GUI 右键「遮挡人脸」与检查器默认同此):不重编码,把内置卡通贴当图片片段放在画面之上、按每条脸轨迹打位置/缩放关键帧(每张脸一条轨),宝宝和家人遮脸的主流做法就是它;`--sticker cloud|smile|bear|star|flower|heart` 换贴,`--size-factor 1.5` 调大小,再跑一次会先清掉旧贴。**像素路径要点名**:`--style blur|mosaic|solid`(或给了 `--box x,y,w,h[@from-to]` / `--no-faces` 也算)才走模糊/马赛克/色块——用户嫌模糊像打码,没要求就别选它;可带 `[--pad-percent 30] [--every 3] [--no-verify]`。像素路径与 `timeline mask` 同构:服务端对 Clip 的源素材跑 `media anonymize`,派生导入为普通资产,Clip 上挂一个 `dev.orangecut.privacy.apply` effect,渲染时换源;模型层的源不动。同一份参数命中派生缓存秒回(`reusedDerivation`)。`--clear` 连派生和贴纸一起清,纯模型编辑一步撤销。结果里的 `faceTracks[]`(每张脸出现的秒段)和 `verification`(还剩几张脸、在哪几帧)要看:`facesFound > 0` 就补 `--box` 再来一次,不要发。派生带原声,联动的声音半边自动跟着换源。**不能与蒙版或变速叠在同一个 Clip 上**(每个派生都从原素材起);先遮脸再变速会被拒,顺序反过来也一样——需要两者时先在文件级 `media anonymize` 出一条新素材再剪。
   - **给一个视频 Clip 挂蒙版**:`oc timeline mask <clip-id> --mask <掩膜文件> [--feather <px>] [--invert] --json`,清除用 `oc timeline mask <clip-id> --clear --json`。掩膜来源同 `media apply-mask`(`oc media segment` 出的掩膜视频,或静态 PNG 整段套用)。**掩膜来源也可以免文件**:`--shape rect|ellipse|linear` + 对应几何参数(与 `media make-mask` 同名同义,画布自动取源素材几何)服务端现生成;或 `--point x,y`(可重复,`neg:` 负点)/`--prompt-box x,y,w,h` + `--frame <源素材帧号>` 走【插件:segment】智能跟踪(未装插件时报 `PLUGIN_NOT_INSTALLED` 带安装指引)——文件/几何/智能三选一。与 apply-mask 的分工:**apply-mask 出的是一个独立文件**,进不进工程、放哪条轨都由你安排;**timeline mask 是工程内语义**——服务端从 Clip 的源素材+掩膜派生出 alpha 抠像、导入为资产、渲染时替换 Clip 的媒体,而**模型层 Clip 的源保持不动**,`--clear` 精确回到原样,undo/redo 走命令通道天然成立。改羽化/反相就重跑一次同命令(effect 原位更新);派生按「源指纹+掩膜内容+参数」缓存,同样输入在本工程里第二次挂是秒回(结果里 `reusedDerivation` 如实标注)。硬约束:只认 asset 源的视觉 Clip;**蒙版后的 Clip 无声**(派生 WebM 不带音轨)——需要原声时把原素材再放一条音轨,linked-AV 的音频半边不受影响;派生对齐的是**整条源素材**,所以之后随意 trim/split 都仍然有效,但源素材很长时先裁短再入轨,别为 3 秒的使用付整部片的派生编码。掩膜文件路径只作为出处记录(`maskFile`),换机器后不需要它仍能渲染。
   - 给一个视频 Clip 加转场:`oc timeline transition <clip-id> --duration-frames <frames> [--easing <曲线>] --json` 与同一 Track 上的前一个 Clip 做交叉淡化——若两者只是首尾相接,出画的 Clip 会被自动延长,在入画 Clip 底下继续播完混合窗口(它需要那么多的额外源素材),全部在一个原子 batch 里完成。`--type fade-in`/`--type fade-out` 则改为用两个线性 opacity 关键帧,把 Clip 自身的不透明度对合成背景做渐变(fade-out 落在最后一个可绘制帧上,不是排他的结束帧)。第一个 Clip 没有可交叉的对象——那里用 fade-in。**`--easing` 决定混合的 α 怎么从 0 走到 1**(只对交叉淡化生效):`linear`(缺省,与从前逐字一致)、`ease-in`、`ease-out`、`ease-in-out`、`smooth`、`ease-in-out-strong`。线性两头都是硬拐点,观感"硬"——**对标片实测用的是四次 S 曲线**(14 帧跨度里前 4 帧只走到 5.5%、中段 6 帧走完 88%、末尾慢收),那一条就是 `ease-in-out-strong`;想要更柔和的中段用 `smooth`。真机实渲逐帧量过 α(纯黑/纯白叠化,帧均值即 α):进度 28.6% 处 linear 0.283 / smooth 0.201 / ease-in-out 0.094 / ease-in-out-strong 0.031,参考值 0.055——四档在成片里分得开,不是只写进参数。缺省不写这个字段,所以老 Project 的规范字节与哈希不变。
   - 给一个 Clip 加随时间变化的曝光/饱和度斜坡:`oc effect exposure <clip-id> [--brightness-percent <n>] [--saturation-percent <n>] [--keyframe PARAM@FRAME=PERCENT[:EASE]]... [--clear] --json`。这是 `canvas grade` 做不到的那件事:调色是整条 Sequence 的一个静态状态,而闪白的意义恰恰在于只存在几帧。100 表示不改动,亮度可以超过 100(闪白本来就是过曝);`--keyframe` 可重复,PARAM 只能是 brightness 或 saturation,FRAME 从 Clip 自身起点算,EASE 是 hold 或 linear(默认 linear)并驱动**从该关键帧开始**的那一段,所以最后一个关键帧的缓动永远不会被用到。两个参数各自保有独立的关键帧网格与缓动,不需要对齐到同一批时间点。没有关键帧的参数就用静态值,不产生任何动画。典型的转场闪白:在切点那一帧给 brightness 一个峰值,前面一个 100 的低点、后面一个 100 的回落点。
   - **给图层加模糊或发光**:`oc effect style <clip-id> [--blur <px>] [--glow <px>] [--glow-color #RRGGBB[AA]] [--glow-strength 1-4] [--keyframe blur|glow@FRAME=PX[:hold|linear]]... [--clear-keyframes] [--clear] --json`。画面片段、抠出来的透明素材、文字贴纸、形状、HTML 卡片都能用(video 轨与 component 轨)。**发光沿图层自己画出来的轮廓走**(alpha 外描 drop-shadow,不是一个方框):抠出来的杯子发蓝光、贴纸的圆角底板一圈光晕、识别框的霓虹描边;`--glow-strength` 是叠几层,1 柔光晕、4 霓虹。`--blur` 糊的是这一层本身——背景虚化让上面的字跳出来、转场前糊一下。长度是画布像素(0–200 / 0–400),预览与导出同一套。**关键帧让光"亮起来"**:`--keyframe glow@0=0 --keyframe glow@12=40`(帧从片段自己起点算,hold 或 linear),两个参数各自一套关键帧。**补丁语义**:没给的字段和关键帧原样保留,重跑只改你给的;给了任何 `--keyframe` 就整组替换,`--clear-keyframes` 只清关键帧。一个片段只有一套(Core 拒绝第二个)。与 `effect exposure` 共用同一条 filter 链(曝光在前),带它的视频片段导出走 classic 路线。
   - 给一个已放置的 Clip 变速:`oc timeline speed <clip-id> --rate-percent 200 --json` 让它以两倍速播放并把时间线长度减半;`--rate-percent 50` 速度减半、长度翻倍。**变速走派生媒体**:引擎没有播放速率原语,所以这条命令会同时用 ffmpeg 把整条源素材重新计时成一条新资产、在同一个原子批里挂到 Clip 上(结果里 `retimedAssetId`/`derivationKey` 如实报告),渲染端看到的是一个以 1 倍速播放的普通元素——这也意味着**命令本身要花一次转码的时间**(与素材长度成正比;派生按「源指纹+速率」缓存,`reusedDerivation: true` 时秒回),素材很长时先裁短再入轨,别为几秒的使用付整部片的派生编码。源里有声音会一并 `atempo`,独立视频 Clip 的声音仍然是对的;联动的画面/声音原子地一起变速,声音半边走导出侧的 atempo 链。之后随意 trim/split 都仍然有效(派生对齐整条源素材)。回到 `--rate-percent 100` 会在同一批里清掉派生。`--freeze`/`--no-freeze` 用一帧定格撑满 Clip 当前长度;`--reverse` 倒放整条源(声音一并 areverse),同样走派生。要"在某帧插入一段定格、后续顺延"而不是定格整个 Clip,用 `oc timeline freeze-frame`(见下)。速率是整数百分比,映射才保持精确;会让 Clip 落在两帧之间的速率,或减速后会压到邻居的 Clip,直接失败而不是四舍五入或覆盖。Clip 上的运动关键帧和效果都会保留——不要为了改速度而删掉重加 Clip。
   - 移除一个 Clip 且不闭合空隙:`oc timeline remove <clip-id> --json`。OrangeCut 在同一事务里自动移除与之精确联动的画面/声音对端。
   - 从精确联动对中分离内嵌音频:用包含 `{"type":"clip.linked-av.detach","payload":{"sequenceId":"...","clipId":"..."}}` 的原始 CommandBatch。核实两个 Clip 都还在、区间不变且不再带 linked-AV 扩展;之后的 split/move/trim/remove 捷径就只影响被指名的那个已分离 Clip。
   - 在整条 Sequence 上开出或闭合一段空隙:`oc timeline gap-insert --at-frame <frame> --duration-frames <frames> --json` 把从该帧起(含)的每个 Clip 和 Caption,在所有 Track 上同时向后移动这么多帧;`oc timeline gap-remove` 用同样方式闭合一段空的空隙,是它的精确逆操作。用它,而不是循环 `timeline move`——那会让你自己算 ripple,还给每个 Clip 留一步 undo。当有 Clip 或 Caption 横跨该位置、锁定的 Track 上有会被移动的内容,或(对 remove)要闭合的区间不为空时,它会在不改动任何东西的前提下被拒绝。多轨项目里 BGM/SFX/贴纸几乎总有横跨的:给 gap-insert 加 `--split-crossing`,横跨的 Clip 会先被逐个切开(联动画音对原子处理,切分视觉零损)再开缝——不必手动收缩一堆 Clip 再还原;带特效的 Clip 和横跨的 Caption 无法切,会带着 id 明确报错。它不关心你要插入什么,所以放章节卡、B-roll 镜头、抖包袱前的呼吸,一视同仁。
   - 在某帧插入定格:`oc timeline freeze-frame <clip-id> --at-frame <frame> --duration-frames <frames> --json` 把该帧的画面钉住这么多帧,后续内容(所有 Track,横跨的 Clip 自动切开)整体顺延——它把「split → 一帧定格派生 → 开缝 → 拉长」四步编排成一条命令。这是多次服务调用的编排而非单个原子事务:中途失败留下的只是切点或一帧定格,不破坏画面,重跑即可续上。
   - 宫格一步到位:`oc timeline grid --clips <id,id,…> [--gap <px>] --json` 把 2–9 个画面 Clip 摆成宫格,一个原子批完成——代替手拼每条完整 transform。布局按画布横竖屏各自定:4 个 = 2×2(`tl,tr,bl,br`,老用法不变);2 个竖屏上下叠、横屏左右并排;3 个 = 一大两小(竖屏上一大下两小,横屏左一大右两小,格子与画面同比零浪费);5–6 个竖屏两列、横屏三列;7–9 个 3×3(不满的最后一带居中)。`--clips` 按阅读顺序(先上后下、先左后右);每格等比缩放装进去,不裁不变形;`--gap` 是格缝与外边距(像素,默认 0;GUI 默认短边 2%)。返回 `grid[].cell` 是每格的 x/y/宽/高。Clip 的入轨与时间对齐仍是你的事(通常四条视频轨、同一段时间区间);记得字幕/贴纸轨要压在宫格轨之上(新建视频轨默认已插在文字类轨道之下)。
   - 摆一个 Clip 的画面位置/缩放/旋转/透明度:`oc clip transform set <clip-id> --x <px> --y <px> --scale-percent <n> --rotation <deg> --opacity-percent <n> --json`——**只传要改的字段,其余保持原值**(裸协议的 `clip.transform.set` 要求六字段全给且是约分 rational,这条命令替你读当前值合并)。`--x/--y` 是盒子中心相对画布中心的像素偏移,右下为正。`oc clip transform clear <clip-id>` 重置回原样铺放。
   - 清空所有 Clip 与 Caption 但保留 Asset:`oc timeline clear --intent "..." --json`。由放置操作自动创建的 Track 清空后被回收;Human 显式创建的 Track 保留。
   - 移除一条未锁定的 Track:`oc track remove <track-id> --json`。仍持有 Clip 或 Caption 的 Track 会被拒绝,除非传 `--with-content`——那会在一个事务、一步 undo 里删掉整条 Track:每个 Clip(联动的画面/声音对会先被 detach,另一条 Track 上的对端得以幸存)、每条 Caption,以及不再被任何东西引用的样式或组件。
   - 重排图层栈:`oc track move <track-id> (--to-top | --to-bottom | --above <track-id> | --below <track-id>) --json`。Track 的 `order` 就是绘制顺序——最顶的 track 画在最前(剪映式:字幕轨通常最顶,主视频轨最底)。一次调用在单个可 undo 的事务里,把所有需要改号的 track 重新编号。
   - 列出 Human 也能点选的现成 HTML 组件:`oc html presets --json`——只给 id、一行描述和创作时长,让 Agent 放置的章节卡、章节进度条、lower third、金句卡、数据行和要点列表与编辑器自带的库完全相同,而不是从零重写。
   - **动态梗贴(会动的叠层)**有两路。**内置的** `oc html add --preset meme-<id>`——纯 CSS/SVG、零素材、任何画布等比、预览与导出逐帧一致:`meme-formulas`(满屏数学公式飘过,懵了/烧脑)、`meme-speedlines`(漫画集中线,震惊/重点来了)、`meme-sparkle`(一簇四角星轮流闪,亮相/高级感)、`meme-circle`(红笔一笔圈出来,画的过程可见)、`meme-arrow`(箭头一戳一戳指过去)、`meme-exclaim`(大红感叹号带爆裂线)、`meme-awkward`(额头垂黑线,无语/冷场)、`meme-dizzy`(头顶转圈星星,晕了)、`meme-question-burst`(满头问号)。位置、大小、颜色都是 `--set=--oc-meme-x=…` 这类变量(画布份额,`oc html presets meme-circle --json` 看全表),各自带一声入场音效(`--sfx none` 关掉)。与 `emote-*`(单个表情图弹一下)互补;要它跟着物体走,放好之后 `timeline follow`。**自带的**:`oc overlay add <file.gif|.png(APNG)|.webp|.webm|.mov | 视频资产 id> --at-frame N [--duration-frames M] [--x px --y px] [--width px] --json`——服务端把动图转成帧可寻址的 VP9 透明 WebM(**`<img>` 里的 GIF 由浏览器按墙钟播,截图取到哪帧看运气**,所以必须转),比 `--duration-frames` 短就循环到正好这么长(`--no-loop` 只播一遍),导入,放到**画面之上、字幕与贴纸之下**的独立 `role=overlay` 视频轨,一个批次一步 undo。`--x/--y` 是距画布中心的像素、`--width` 是渲染宽(缺省短边 30%)。动图 WebP、GIF、APNG、ProRes 4444/PNG 编码 MOV、VP9 alpha WebM 的透明通道都保住;结果的 `conversion.transparentShare` 是一帧里透明像素的占比,源本身不透明(比如绿幕 mp4)会报 `OVERLAY_NOT_TRANSPARENT`——那样贴上去就是个方块,先 `media matte` 抠。
   - 把一个 fragment 文件编译成组件实际携带的类型化节点树,不需要 Project 也不需要服务:`oc html compile <fragment>.html --json`。它应用与 `oc html add` 完全相同的规则——恢复 SVG 大小写、`id` 折叠进 class、`style` 拆进样式表、裸文本包裹以保序——并交回 `componentType`、`capabilityRequirements` 与 `properties`。当你要提前生产组件或用别的工具产出时用它,免得重新实现这些规则然后跑偏。带 `data-form-label` 的文本节点在编辑器属性表单里给自己的字段命名;没有的话,表单先回落到 preset 目录,再回落到文本本身。
   - **录屏包装**:`oc html screen <录屏绝对路径> --clicks "t:x,y;t:x,y" --at-frame N [--device auto|window|laptop|phone|none] [--zoom 1.8] [--hold 1.4] [--background <css>] [--no-cursor] [--sfx dianji|none] --json`——一步把录屏套上背景与设备框(竖屏自动手机框),每次点击前 0.55 秒镜头推近到点击处、停 `--hold` 秒再拉回(相邻点击直接平移不拉远,推近时不露框外空白),画光标(录屏没录到也有)与点击涟漪,每次点击挂一声点击音效。`--clicks` 的时间是相对录屏开头的秒、坐标是录屏自身像素;录屏以 `<video data-asset-id>` 嵌在组件里,时长等于录屏。做画中画:`--background transparent` 后 `oc clip transform set <clip> --scale-percent 46 --x … --y …`。
   - **信息层与联动四件**:`info-textwall`(文本墙:压暗背景、标题逐字打出、段落依次亮起缓缓上滚,`--set paragraphs='[{"text":…}]'`)、`info-cloud`(文字云:短句散落、大小错落、依次亮起漂移,`--set phrases='[…]'`;前景层再放一个并 `--set=--oc-cloud-scale=1.9 --set=--oc-cloud-blur=.5cqmin --set=--oc-cloud-shift="0cqw 62cqh"`)、`info-flow`(原理流程图:三到五张编号卡片排成一行,依次点亮,光点沿连线跑到下一步,`--set steps='[{"title":"手机里点一下","note":"打开模型"},…]'`,节奏 `--set=--oc-flow-step=.9s`,时长至少 lead + 步数 × step,讲原理不讲术语)、`link-trigger`(虚实联动:起点涟漪 → 光点沿弧线飞到终点 → 终点亮起弹标签,坐标用 `--set=--oc-link-ax/ay/bx/by=…cqw/cqh`)。文字夹在背景和主体之间:主体 `media matte` 抠出来放上层轨,`track move --above <组件轨>`。
   - 每个 preset 都是参数化的:具名文字槽位、列表槽位,以及覆盖颜色、字体和所有长度的 CSS 变量。全部可选,且每个默认值就是推荐值,所以不带 `--set` 放置的 preset 就是对的。只有当你打算改什么时,才去读某个 preset 的属性名、默认值和含义:`oc html presets <preset-id> --json`。不要猜属性名;这份列表是权威,未知的名字会带着完整集合被拒绝。
   - 长度按画布的份额书写,绝不用像素,这样 preset 在任何导出尺寸下都保持比例。你传的值遵循同一规则:优先 `cqw`(1cqw = 视频宽度的 1%)而不是 `px`。
   - 放置一个这样的 preset:`oc html add --preset chapter-card --set eyebrow=下午 --set title="回到工位" --set=--oc-ch-bg=#101014 --at-frame <frame> --json`。CSS 变量以 `--` 开头,所以要用 `--set=<name>=<value>` 连写;分开写会被当成 flag 拒绝。省略 `--duration-frames` 就取 preset 的创作时长,按 Sequence 自己的帧率换算。槽位值被转义进文本位置,所以开不了标签。每个 preset 还带自己的 `placement`:`overlay` 落在画面之上、下面的内容继续播;`insert` 先在所有 Track 上开出空隙,让这一块占据自己的时间——整次放置仍是一个原子事务、一步 undo。只有要覆盖 preset 自己的设定时才传 `--placement overlay|insert`。
   - 用 `--set <list>='[{...},{...}]'` 填充 preset 的重复结构——章节进度条的段、排行榜的行:`oc html add --preset chapter-bar --set chapters='[{"title":"开场","seconds":20},{"title":"关键数据","seconds":40}]' --at-frame 0 --duration-frames <whole sequence> --json`。每个条目在权重总和中的份额,成为它的宽度和它自己的上屏窗口;总和被写进 preset 的时长变量,进度条与视频对得上,不用你做算术。烧录的进度条横跨整条 Sequence,所以要等剪法定稿后再放:它在时间线上时,会横跨 `timeline gap-insert` 可能打开的每一个位置,那次 insert 会被拒绝而不是把它劈开。结构性改动后重新放置。
   - 音效默认跟随入场:四十九个综艺音效随 OrangeCut 本体内置,打开时以 `asset-bundled-sfx-*` 音频 asset 装进每个 Project(GUI 素材面板的 内置 tab 与 CLI 看到同一批 asset;`ORANGECUT_SFX_DIR` 可整体换成自定义文件库)。每条带 `use`——一句话说它适合的场景(`oc sfx list --json` 里能看到),选声先按 use 对情绪,再按 kind 对落点;全部已归一到 I=-19 LUFS,不用再单独调音量。`oc html add --preset chapter-card ...` 放 preset 声明的 kind(chapter-card/chapter-scrim→impact,title-card→whoosh);`oc sticker add --preset ...` 从入场动画推导音效(pop→pop,zoom→impact,bounce→boing,slide→whoosh;fade/none 保持无声)。两者都落在专用的 `role=sfx` 音频轨上,并与视觉 clip 联动。单条大字强调卡(关键词大字/数字/气泡/金句)是文字贴纸 preset——例如 `oc sticker add "搞钱思维" --preset keyword_yellow` / `bubble_white` / `quote_black` / `mega_impact`——不是 HTML 组件。打击类 kind 落在入场帧上;whoosh 提前一帧。传 `--sfx none` 跳过,`--sfx <id|kind>` 覆盖;fragment 文件除非 `--sfx` 指明,否则不带声音。若卡片落地后声音那一半失败,错误会点名 clip,一条 `oc sfx set` 就能补完。

   - **插梗(切出镜头 / cutaway)**:综艺和短视频最高频的注解手法——一句话说完、笑点落地、需要"观众反应"的那一刻,插一段一两秒的反应片段(土拨鼠尖叫、真香、扶额无语……),借观众已有的记忆一秒完成情绪标注,相当于喜剧的罐头笑声。十四条剪映素材库里使用次数最高的片段随 OrangeCut 内置(`asset-bundled-cutaway-*` 视频 asset,GUI 内置面板同一批):`oc cutaway list --json` 看 id、kind(reaction 反应 / timecard 时间卡 / outro 引导关注)与一句话用法,不需要服务。`oc cutaway add <id|视频 asset id> --at-frame <frame> --json` 默认 **insert(串联)**:把主画面轨在这一帧切开,按 `gap-insert --split-crossing` 的规矩全轨道撑开一段缝(人声、字幕、BGM 一起后移,同步不乱),片段填进主画面轨的缝里——前面的画面停下,片段放完再接着播;片段按 `--fit contain`(默认)保持宽高比显示完整,宽高比不同就上下或左右留黑边,`--fit cover` 铺满裁切。叠层的两种放法是显式选项:`--mode overlay` 另开一条垫在字幕之下的 `role=cutaway` 视频轨盖在画面上、人声与下面的一切照常播(contain 时四周露出原画面);`--mode pip` 在 overlay 基础上缩到角落(`--pip-scale-percent 45` 占画布宽度、`--pip-corner top-right`)。`--duration-frames` 封顶时长,`--volume-percent` 调片段自带的声音(0 只留画面)。自己攒的梗片段 `oc asset import` 后按 asset id 走同一条命令;放置回执 `data.cutaway` 带 clipId/trackId。**用法上的默认**:一次只插一条、两秒以内、接在句尾而不是句中(ASR 词时间就是句尾),三十秒里最多两三次,一条片里同一个梗不重复;梗不是每个账号都合适,严肃、知识向的号先问再插。
   - 音效密度是随视频形态而定的编辑选择,不是固定规则。留人型快剪(综艺文字贴纸、盘点倒数)几乎每张卡配一声,3–8 秒一个。常规知识/口播片在 45 秒里只在最重要的节拍上落 5–7 声,普通字幕行保持无声。安静的叙事片或金句卡片,可能只在章节卡和收尾句要声音——或干脆全无。无论形态:绝不在同一时刻叠两个音效,音效垫底永远压在人声之下(参考混音是人声 loudnorm I=-15,sfx I=-19)。

   - **先量再定音量**:`oc audio measure <clip-id> --json` 按这条 Clip 实际用到的源区间量它的积分响度(`integratedLufs`,BS.1770)、真峰值(`truePeakDbtp`)与响度范围,并算出加上 Clip 自己增益后的 `effectiveLufs`——这是 `--gain-percent` 该填多少的唯一依据,手机原声、TTS 配音、BGM 三种来源的录制电平差二三十分贝,靠听感试是最慢的路。`oc audio level <clip-id> --target-lufs -16 --json` 量完直接把增益设到位(`--like <clip-id>` 则对齐到另一条 Clip 的生效响度,原声段对齐配音段用这个);`--max-boost-db`(默认 12)封顶抬升——录得太轻的源抬上去的是底噪不是人声,封顶了会在结果里报 `clamped: true`,该换 `oc audio denoise` 或换素材,不该硬抬。`--dry-run` 只算不写。经验值:口播 -16,整条混音 -14,压在人声下面的音乐约 -28(再配 `audio duck`);**gain 15% 又不闪避的 BGM 比旁白低约 26 dB,手机外放等于没有**。
   - 让解说压住背景音乐:`oc audio duck <music-clip-id> --over <spans.json> [--gain-percent 25] [--fade-frames 6] --json`。spans 与 `timeline place` 的剪单同形状(`atFrame` / `durationFrames`),典型来源是对解说音轨跑 `oc media silence` 拿 `keepSpans`。**音乐 Clip 保持完整**——它写的是 `dev.orangecut.audio.mix` 效果 gain 参数上的关键帧包络(降到位、压住、开始抬、抬回原位四个点),这也是 Premiere 的做法;切分时间线是没有哪款剪辑软件会做的事,切碎之后事后没法调整。四个细节由它照顾:① 已有的音量成为「没被压时」的取值,不会把音乐床原本的 40% 悄悄抬回 100%;② 相邻区间的斜坡撞在同一帧时取更低的值——让音乐短暂弹回原音量比继续压着更刺耳,而且 Core 拒绝同一时刻两个关键帧;③ 关键帧时间锚在 Clip 自己的起点上,与视觉关键帧同一条约定;④ **重跑就整体替换上一次的包络**——Adobe 的自动闪避有个众所周知的限制:关键帧是生成那一刻写下的,之后挪动对白或音乐它不会跟着更新;我们同样躲不掉,所以挪动之后重跑一次即可。GUI 里看得见:时间线上蓝色菱形标出每个关键帧,属性面板会说明音量随时间变化、静态值当前不参与。预览与导出共用 `fixtures/rendering/audio-gain-envelope.json` 这份求值契约。
   - 设定出片响度目标:`oc audio loudness --target-lufs -14 --json`,`--clear` 关掉。它是**发布策略**不是剪辑动作——不动时间线上任何东西,只在导出收尾时把整条混音乘一个标量增益。多素材拼接时音量忽大忽小是观感上最刺耳的缺陷,而各段素材的录制电平本来就不一样,这条是唯一的统一口。值必须为负(相对满刻度):`-14` 是流媒体常用,`-16` 适合以人声为主的口播。**代价要知道**:设了它,导出会多跑一遍测量——把整条音轨解码并混一次,长片上是实打实的时间,所以默认关闭。归一化的增益挂在限幅器之前,先抬到目标再守天花板;单遍 `loudnorm` 那种边走边压的动态归一化既到不了目标值又会改动态,所以引擎坚持两遍。
   - 列出独立计时的 Caption、`emphases` 关键词高亮及其解析后的样式:`oc caption list --json`。
   - 在 Caption Track 上按精确帧添加一条 Caption:`oc caption add "文字" --at-frame <frame> --duration-frames <frames> --font-asset-id <font-asset-id> --json`。返回的 `data.layout` 是这条字幕的占位检查(和贴纸/形状撞没撞、竖屏有没有进遮挡区),`warningCount > 0` 就当场改。可选样式 flag 包括 `--font-size`、`--color`、`--font-weight normal|bold`、`--font-style normal|italic`、`--underline`、`--align`、`--position`(缺省 `bottom`;**竖屏画布上 bottom 落在画面高度 76% 处、top 在 15%**,躲开抖音/TikTok 顶部与底部的界面遮挡区,横屏与方形仍是 10%/90%,全是画布高的比例)、`--x/--y`、`--rotation`、`--scale-percent`,以及描边/底色/阴影字段。需要时,OrangeCut 在一个事务里创建私有样式 Component 和一条未锁定的 Caption Track。用 `--emphasis 抢着买=#3DDC84` 给关键词持久上色(可重复;该文本的每次出现,在这条 caption 的整个生命期内都渲染成该颜色——与 `--highlight word` 是两个不同的工具,后者随语音进度逐词重绘,两者同设时后者胜出)。`oc caption update <id> --emphasis ... | --clear-emphases` 替换或移除该集合;`add-batch` 的条目可以逐行携带 `"emphases": [{"text", "color"}]`。

   - **拿台词先查字幕轨,再考虑 ASR**:`oc media subtitles <absolute-path> [--language zh|en] --json` 列出这条片子的全部字幕轨——同目录同名的 .srt/.ass/.ssa 文件和容器内嵌的文本轨,每条带 admission 判定(cue 太少/只盖住片长一角/forced 招牌轨/PGS·VobSub 位图轨都会给出拒绝理由;"找到但不能用"和"根本没有"是两个答案)。加 `--read` 取回 cue 全文(恰好一条可用轨才自动选;多条报 `SUBTITLES_AMBIGUOUS` 等你 `--track` 点名,绝不替用户猜)。正版片源的字幕在**专有名词上通常比 ASR 准**(写它的人知道名字怎么写),而且是毫秒级文件读取、零 GPU;GB18030/Big5 老编码和双语轨(`--language` 取行)都处理好了。两个如实的短板:cue 时间是**显示时间**(带提前进入/延迟退出,比 ASR 词级时间戳粗,烧字幕够用、卡帧要留神);不校验轨与这版剪辑是否同步。全片烧录的硬字幕不在此列——那是像素,走【插件:ocr】。
   - 不出这台机器就把语音转成定时文本:`oc media transcribe <absolute-path> [--srt out.srt] [--glossary 词表.json] --json`。不需要打开的 Project,也不需要网络:OrangeCut 用自带的 ffmpeg 解码文件音频,跑内置的离线中文优先 ASR(Paraformer + 标点恢复 + 语音活动切分),返回带标点的句级 `segments` 和字级 `words`,各带起止秒数(字段名是 `start`/`end`)。**词级时间戳是真的逐词计时,不是把句子等分插值**——实测一条 44 秒解说出 24 段 175 词,词时长 min 0.060 / max 0.580 / mean 0.219 秒,所以可以拿来卡帧;云端 ASR 返回的等分插值时间戳做不到这件事。识别引擎(sidecar)随分发包走,但 340MB 的模型是【插件:asr】——首次用前 `oc plugin add asr`(跨平台,不需要 GPU,是唯一在 Mac 上也可装的模型包之一)。没装时报的是 `ASR_RUNTIME_UNAVAILABLE`(不是 `PLUGIN_NOT_INSTALLED`,但 `remediation` 同样带着安装命令,照做即可);`ORANGECUT_ASR_RUNTIME_DIR` 只在开发树里指向自建运行时时才需要。`--srt` 同时把句子写成可直接给 `caption import-srt` 用的 SRT 文件。运行时长约为音频长度的 1/20;CLI 已经等得足够久,不要再包一层你自己的超时。同音字滑笔(它/他)、专有名词和数字格式是已知的错误类别——烧进字幕前先对着上下文校对文本。重背景音乐或对白重叠会削弱任何 ASR;这类素材上接近全空的结果应视为预期,而非缺陷。**专名修不好就上 `--glossary`**:JSON 形如 `{"terms":[{"canonical":"安欣","aliases":["安心"]}]}`,转写后做确定性纠错——别名精确直替 + 带调逐字同音替换("安心"→"安欣"改,"暗心"声调不对不改),单个汉字的词条一律拒绝(单字会命中普通词内部,"操"→"曹操"曾把"操碎了心"改成"曹操碎了心")。只改 `segments`/`text`/`srt`,`words` 保持原样(词级条目的价值在计时不在字面);结果的 `glossary.corrections` 如实列出每一处替换,烧字幕前扫一眼。**词表有全局的一份**(机器级,跨工程复用,与桌面「设置 → 转写词表」同一个文件):`oc glossary list` 看现表,`oc glossary add <正名> [别名…]` 加一条(同正名合并别名),`oc glossary rm <正名>` 删一条,`oc glossary set --file 词表.json`(或 `--clear`)整表替换。全局词表对每次 `media transcribe` 与 GUI 一键转写自动生效,`--glossary` 只是这一次再叠加几条;用户反复纠同一个专名时,把它加进全局表而不是每次传文件。
   - **手里有稿子就让字幕用稿子的字**:`oc media transcribe <path> --script 稿子.txt [--max-line-width 18] --srt out.srt --json`。稿子(UTF-8,一行一句或带标点都行)与 ASR 做字级对齐:**上屏的是稿子的字**(同音字、"40千克"这类数字写法、专名都以稿子为准),时间借 ASR 的逐字时间轴——只有一字不差的匹配当锚点,两个锚点之间念到的那段时间按停顿成簇、均分给稿子的字,新子句开头取停顿之后那一簇(不会被前面的杂音拉早)。切分规则与普通转写同一份(子句、单行、无标点、不劈词)。结果:`segments`/`srt`/`text` 是稿子的,`words` 是**稿子的逐字时间**(直接喂 `caption import-srt --words` 做逐字高亮),原 ASR 留在 `asrText`/`asrWords`;`scriptAlignment` 报 `coverage`(稿子对上的比例)与三类段落——`unspokenSpans`(稿子写了没念)、`extraSpeechSpans`(念了稿子没有:即兴、对白)、`mismatchedSpans`(同一位置念的和写的是两回事),对上比例 <60% 带 `warning`(多半拿错了稿子)。**这三类段落要看**:没念的那句别烧进字幕,稿外的对白要么补字幕要么确认不要。实测对标片 65 秒:字幕起点误差中位 0.075s→0.057s。`--max-line-width` 是一条字幕的最大宽度(CJK 当量,ASCII 算 0.55,缺省 14 是竖屏短视频的量),**横屏中长视频字小、一行放得下更多,18 左右**;不给稿子时也能单独用,只按新宽度重切 ASR 自己的全文。
   - 分析音轨的节拍与重音:`oc media beats <absolute-path> [--from-sec S] [--to-sec S] [--top-hits N] --json`。不需要打开的 Project,音频视频都吃(视频取其音轨)。返回 `bpm`(基频)、`tempoCandidates`(基频往下每次折半的候选分频)、等距推演的 `beats` 拍点、每 4 拍一个的 `downbeats`、能量最强一段的起点 `peakWindowStartSec`(通常是副歌/drop),以及 `hits`——按电平跃升排序的重音时刻,各带 `jumpDb` 与跃升后的 `levelDb`。这是 Audio-first 的另一半:此前音频侧只有 ASR,有人声才拿得到东西,纯音乐什么都给不了,而每个卡音乐的形态都需要它。**拍点网格与重音时刻会给出不同答案,这是刻意的**:网格是等距推演(稳,适合串起一排硬切),重音是实测跃升(准,适合把某一刀压在点上);真实演奏并不严格落在网格上,实测同一条 BGM 两者可差 22ms,足够让观感"没对齐"。要串一排镜头用 `downbeats`,要压准一刀用 `hits`——**网格不要直接当卡点用**:六条真实 BGM 实测,重音到最近拍点的中位距离是 68ms(约 5-11% 拍长),落刀时该拿网格附近的 `hits` 去吸附。个别曲子偏离能到 40% 拍长,那是它本身就不规整(切分、自由速度),**这时也不要拿 `hits` 反推等距网格**——重音自己并不等距(切分音、采样噪声都在里面),实测这样推出的网格比原网格更差(一条从 7% 恶化到 27%)。偏离大就说明这首歌不适合等距卡点,该换歌或改成只在少数几个 `hits` 上落刀。职责边界同 faces:OC 只给测量,哪一拍该切、hero 放哪个重音上属于 Agent——**该用哪一档分频也是**:同一首歌数每一拍还是每两拍都对,取哪个取决于想要多密的切点,所以引擎报基频与候选档、不替调用方选。按形态挑即可(如"镜头中位 1.0-1.3s"就取`60/bpm` 最接近 1.15 的那一档);档位只能翻倍所以是离散的,目标区间可能整个落在两档之间(实测基频 178.5 的曲子候选是 0.336/0.672/1.345),取最接近的那档就是最优解。**拍点是切点,不是覆盖计划**——拿拍点当剪单时间时,三个天然漏画面的位置要自己盖住,漏出来的全是黑帧(实拍两条卡点成片踩过):① 第 0 帧到第一拍——`beats[0]` 几乎从不在 0(实测 0.02s),首 clip 要从第 0 帧铺起,不是从第一拍;② 拍与拍之间——拍长几乎从不是整数帧(0.474s ≈ 14.22 帧),取整后拍距会在相邻两个帧数间跳动(14/15 交替),素材恰好"一个名义拍长"时,凡是长一帧的拍距就漏 1 帧黑,每段素材要铺到**下一拍的实际落点**;③ 最后一拍到序列末——按 BGM 长度定的时长通常比最后一拍多出几帧,尾 clip 延过去或把时长裁到画面结束处。铺完跑 `oc layout check`,`coverage` 会把三类黑场全数报出。
   - **量画面的色彩底子**:`oc media colorstats <absolute-path> [--every N] [--from-sec S] [--to-sec S] --json`。不需要打开的 Project,约每秒采一帧缩到 96² 统计,返回 `summary`(luma 亮度 0-1、saturation 饱和度 0-1、warmth 冷暖 −1..1 正为暖、skinShare 肤色占比、darkShare 暗部占比、contrast 亮度标准差)与 `verdicts` 五个判定词(`lighting: dark|dim|normal|bright`、`temperature: cool|neutral|warm`、`saturation: muted|normal|vivid`、`skin: none|some|prominent`、`contrast: flat|normal|punchy`),外加最多 600 条逐帧明细看走向。它是"调色顾问"的证据来源:**先量再推荐**,"这段素材整体偏暗偏冷、肤色占三成"比"这是旅拍所以用日系"站得住。阈值是经验值不是标准,数字是 sRGB 上的人眼尺度,别拿去做精确色彩数学;**`skinShare` 认的是 YCbCr 肤色区,暖棕色的毛发、木头、沙土也会算进去**——实测一条狗的特写报 0.30,把它读成"暖棕肤色调占比",配合 `faces` 才能确认真有人。
   - 扫成片的上下黑边:`oc media letterbox <absolute-path> [--every N] [--source-dir <素材目录>] --json`。不需要打开的 Project:逐帧量出每个可疑帧上下各有多少像素的黑边,返回 `frames`(帧号、秒数、topPx、bottomPx)与 `maxBandPx`,空数组即这条片子干净;**整帧全黑单独报在 `blackFrames`**——上下都吃到几何上限且画面正中也黑时,那不是"画面被挤扁"而是切点上漏出的空帧/未就绪帧,成因与处置都不同,混在一起报会让人去查错方向。**默认逐帧扫**——黑边常常只在少数端点帧露出来,抽几个时间点看很容易全部落在放大区间而给出假阴性(实测踩过)。三条判据依次收紧:几何(只认画高 12% 以内的边,更厚的是信箱式构图不是适配事故)、亮度(整行均值与峰值都要够低,且用三通道最大值而非灰度,免得暗红布料被当成黑边)、以及**与源素材同刻比对**——`--source-dir` 给了才启用,它是唯一能分开"深色内容贴着画面边缘"与"适配露出黑边"的判据(实测有人物穿深色衣服贴底边的镜头行均亮度接近零,前两条完全分不开),没给时 `sourceCompared` 报 false,同时 `frames` 里每一帧都带 `sourceCompared: false`、结果里多一条 `PENDING_SOURCE_COMPARISON` 警告——**这一档的 `maxBandPx` 是"疑似"不是"确诊"**,实测有整组 132 个可疑帧在补上 `--source-dir` 后归零,全是深色内容贴边。职责边界同 faces:OC 只报黑边有多高,"这条能不能发"属于 Agent。
   - **把主体切出来当遮挡层**(让文字/图形被人挡住):`oc media matte <absolute-path> --output <file.webm> [--feather <px>] [--invert] --json`。不需要打开的 Project。产出是带透明通道的 WebM(VP9 `yuva420p`——带 alpha 的编码里只有它渲染器能直接解),**不含音频**:这一层是压在上面的画面,把原声再混一遍只会让同一段声音响两次。典型用法是三层:底下原片、中间字幕/字卡、上面这一层,文字就走到人身后去了。前景/背景两层不需要新命令——同一个 asset 用 `timeline add --new-track` 放两次、`track move` 定层序即可。**它刻意不是抠像**:掩膜是 192×192 的分割放大来的(同 `media subject`),软边正好藏在文字边缘下,但拿去做**背景替换、主体描边、发光**就会在纯色底上露出一圈毛边——那些要发丝级、时序稳定的 alpha,得换抠像模型,不是这条命令能补的。**要发丝级就加 `--quality high`**【插件:matting】:走 MatAnyone 2 抠像插件(懒调用,未装时报错自带安装指引;只在有 NVIDIA GPU 的机器可用,约 0.4 秒/帧),全分辨率软 alpha,发丝和半透明衣摆都保得住,羽化缺省归零。没装插件时会报 `PLUGIN_NOT_INSTALLED` 并附安装命令。结果里 `maskSource` 如实写着掩膜怎么来的,`coveragePercentMean` 太接近 0 或 100 说明这条素材不适合抠,**`framesWithoutSubject` 是必须看的一项**:那些帧里主体会凭空消失一下(反相时相反)。`--feather` 缺省 2 像素(盖住放大的台阶),`--invert` 留背景抠主体。逐帧分割加一次 VP9 编码比 `media subject` 慢一个量级,长素材几分钟很正常。
   - **掩膜现成时,套掩膜用这条**:`oc media apply-mask <absolute-path> --mask <掩膜> --output <file.webm> [--feather <px>] [--invert] --json`。不需要打开的 Project。`matte` 是"自己算掩膜再合成",这条是"掩膜从外面来"——典型来源是 `oc media segment` 出的掩膜视频(白=保留),也收单帧 PNG(静态图整段套用,适合固定区域挖空/保留)。产出与 `matte` 完全同规格的 VP9 alpha WebM(不含音频,轨道玩法同上),羽化算法与编码参数一字不差,别再手写 ffmpeg alphamerge。帧同步语义:掩膜视频按时间戳对齐,帧率不同会重复/丢帧;**掩膜比素材短时最后一帧续用到片尾**,掩膜分辨率不同会被缩放到素材几何——这两条都是兜底不是功能,掩膜和素材同源生成才是正路。结果里 `frames` 探测的是输出实际帧数,`maskKind` 写明用的是视频还是静态图。一次 VP9 编码,长素材分钟级。
   - **几何蒙版不需要分割模型**:`oc media make-mask --output <mask.png> (--like <media> | --size WxH) --shape rect|ellipse|linear <形状参数> [--softness <px>] [--invert] --json`——渐变压暗、分屏、聚光这些场景是纯几何,直接生成掩膜再喂给 `apply-mask` 或 `timeline mask`。形状参数:rect 用 `--box x,y,w,h`;ellipse 用 `--center x,y --radius r|rx,ry`;linear 用 `--position 0..1 [--angle 度]`(0° = 白在左、分界线沿渐变方向推进)。`--softness` 是边缘软化带宽(缺省 0 硬边;linear 的柔和渐变靠它)。**移动遮罩**:加任意 `--end-box/--end-center/--end-radius/--end-position` + `--frames N [--fps R]`,输出改 `.mp4`,起止态逐帧线性插值——扫光、开幕、分界线推移都是这一条。结果里 `coveragePercent` 是首帧白色占比,画完先看它对不对再往下走。秒级,不需要打开的 Project。
   - 量一段画面动不动:`oc media analyze <absolute-path> --motion [--from-sec S] [--to-sec S] --json`。不需要打开的 Project:逐帧(缩小后)取相邻帧平均绝对亮度差(与 ffmpeg signalstats 的 YDIF 同一把尺子,0..255),返回整体 `meanYdif`/`maxYdif`、按秒的 `windows`,和一个 `verdict`(`static` <2 基本死图 / `subtle` <6 轻微 / `moving`)。选镜头时先跑它筛掉死素材;哪一档能用属于 Agent——定格感是不是要的效果只有你知道。
   - 量一个文件多响:`oc media loudness <absolute-path> [--from-sec S] [--to-sec S] --json`。不需要打开的 Project:同一把尺子(ffmpeg `loudnorm`,也是导出收尾归一化用的那遍)量出 `integratedLufs`、`truePeakDbtp`、`loudnessRangeLu`;整段数字静音时各项为 null 且 `silent: true`,不给哨兵数字。项目内的 Clip 用 `oc audio measure` 更直接(它替你按源区间收窄)。职责边界同 silence:OC 只报多响,"该调到多响"属于 Agent。
   - 量一条音轨在哪里安静下来:`oc media silence <absolute-path> [--threshold-db -35] [--min-duration-sec 0.35] [--pad-ms 60] --json`。不需要打开的 Project:返回 `spans`(静音段)、`keepSpans`(它们的补集,直接可以拼剪单,省掉各自求补集时最容易漏的首尾那一段)、以及这条音轨自己的 `noiseFloorDb` 与 `speechLevelDb`。**阈值是绝对的,用之前必须先看 `speechLevelDb`**——录得轻的素材整条都在 -35 以下,那样会测出"整条都是静音";`belowThresholdRatio` 接近 1 就是阈值选错了的信号,该按这条音轨自己的电平重新给一个。两件它刻意不做的事:**不保证不切在词中间**(那要 `oc media transcribe` 的词级时间戳,正确用法是与词边界求交,只在两边都同意处落刀);**不自动补安全边距**(贴边切会削掉辅音起头,但补多少是形态决策,所以留成 `--pad-ms` 由你给,默认 0)。职责边界同 letterbox:OC 只报哪里安静,"该不该真剪"属于 Agent。
   - **叠层跟着画面里的东西走(物体跟踪)**:`oc timeline follow <叠层 clip-id> --target <视频 clip-id> --box x,y,w,h [--at-frame <时间线帧>] [--scale none|uniform|box] [--offset=dx,dy | --center] --json`。叠层可以是文字贴纸、形状、HTML 组件、图片、动态贴纸——识别框框住杯子、箭头指着按钮、卡通小人站在语音板旁边、光效罩着被抓起的东西,都是这一条。`--box` 是**画布像素**、画在 `--at-frame` 那一帧上(就是 `oc read --frames <帧>` 看到的那张图,缺省是叠层与目标重叠的第一帧),框要贴着**有纹理或边缘**的东西(一面白墙跟不住,会被拒)。服务端内置模板跟踪(CPU、无插件,目标长边缩到约 40 像素再找,63 帧 1.2 秒),参考帧前后两个方向都跟,丢失的帧保持原位并如实报 `lostFrames`/`lostSpans`(时间线帧);丢失超过三成带 `FOLLOW_TRACK_UNRELIABLE`。然后**一次** `visual.motion.replace` 写位置关键帧(缺省每 2 帧一个,`--step` 调,每条曲线封顶 600 个):**缺省保持叠层现在相对物体的位置**——先用 `sticker add --x --y` 把贴纸摆到参考帧上物体旁边该在的地方,再 follow,它就一直待在那个相对位置;`--center` 压在物体中心,`--offset=dx,dy` 显式给(负数要写成 `--offset=-30,10`)。`--scale uniform` 随物体面积等比缩放,`--scale box` 宽高各自跟着变——画一个 `oc shape add rectangle`(透明填充、描边)框住物体再 `--scale box`,就是对标片里那种跟着物体走的识别框。已有的旋转/不透明度关键帧保留。`--clear` 撤掉位置与缩放关键帧,undo/redo 照常。**要更准就先分割**:`oc media segment <源> --output mask.mp4 --box … --frame N`【插件:segment】出掩膜视频,再 `--mask mask.mp4` 代替 `--box`,逐帧取掩膜外接框——遮挡、旋转、形变都稳;实测同一段杯子镜头,模板跟踪中心误差中位 9.5px/最大 37px,掩膜路径 4.3px/9.9px。两个硬约束:目标片段变过速/倒放/定格会被拒(`FOLLOW_TARGET_RETIMED`,画面不再逐帧对应源素材——先 follow 再变速);目标片段自己有位置/缩放动画时只按静态变换换算,带 `FOLLOW_TARGET_ANIMATED` 警告。只要轨迹不要关键帧时用 `oc media track <path> --box x,y,w,h --frame <源帧> [--from-frame] [--to-frame] [--mask m.mp4] --json`:源像素、源帧号,逐帧 `boxes[]`(带 `score`/`lost`),不需要打开的 Project。**跨镜头剪切不保证身份**:一个镜头一个镜头地跟。
   - **跟踪人脸**:`oc media face-tracks <absolute-path> [--every 3] [--min-face-px 0] [--hold-sec 0.5] [--lead-sec 0.2] [--pad-percent 30] --json`。不需要打开的 Project,内置检测器,不用插件:把采样帧上的检测串成逐脸轨迹 `tracks[]`(`id`、`firstFrame/lastFrame`、`firstSec/lastSec`、`samples`,以及**逐帧**的 `boxes[]`——已按中心外扩 pad%、顶部多留 15% 盖发际线、三点平滑、采样之间线性插值、首尾各外延 lead 秒)。断档不超过 hold 秒的算同一条。这是任何遮挡物(像素级或贴纸)要跟的几何,也是"这条素材里谁露了脸、露了多久"的清单——选段前跑一遍,比抽帧肉眼核快得多。
   - **遮挡人脸 / 任意区域(文件级)**:`oc media anonymize <absolute-path> --output <out.mp4> [--style blur|mosaic|solid] [--no-faces] [--box x,y,w,h[@from-to] ...] [--pad-percent 30] [--every 3] [--no-verify] --json`。跟踪 + 椭圆软边区域内做模糊(真正高斯模糊，强度可调)/ 马赛克(块按脸宽 1/8)/ 色块,产出**与源逐帧对齐、率 1、带原声**的派生 mp4(联动的两半要共用它);`--box` 是源像素的手动区域(漏检的脸、车牌、屏幕),可带秒级时间段;`--no-faces` 只盖手动框。**默认遮完再检一遍**:结果 `verification.facesFound` 该是 0,`frames[]` 列出还检得出脸的帧号；这只是抽样检测结果，仍须检查整段画面。项目内的 Clip 用下面的 `oc timeline privacy`,它替你派生、导入、换源。
   - 检出媒体文件里的人脸:`oc media faces <absolute-path> [--every N] [--frames a,b,c] [--face i] [--output out.png] [--no-sheet] --json`。不需要打开的 Project:内置检测器(YuNet,五点关键点,已随二进制打包)逐采样帧返回每张脸的 `box`(源像素坐标)、`landmarks`(双眼/鼻尖/双嘴角)与置信度,并默认渲染一张**按帧号标注的抠脸拼图**(每格 `f帧号#脸序`,统一放大到 ≥320px 可视尺寸,多页自动分页)。这是 AI 生成素材质检的正确入口——整帧缩略图里 60px 的小脸永远看不出五官崩坏,抠脸拼图把"看对地方、看对尺度"变成机械保证;`noFaceFrames`(采样过却零检出的帧)是最强的重度崩坏预筛信号。每张脸附带程序化质量预筛(lint 语义,零模型四信号,阈值标定于真实标注集):`small-face`(<60px,像素预算不足脸必不可信)、`eyes-low-detail`(正脸且瞳距 <40px——**脸完好眼必崩**的高危区,眼崩的本质是眼部像素预算)、`landmark-jitter`(跨帧关键点跳变=形变/遮挡)、`low-confidence`;`eyeSymmetry` 仅作测量值报告(低头/侧转姿势与真形变在该指标上不可分,不触发标记)。**拼图默认只渲可疑脸**(高频场景=找问题;全绿时零图片产出,读 JSON 的 `suspectsTotal: 0` 即放行),背景小脸的告警只留 JSON 不上图;`--all` 全量渲染,用于新场景首批素材的抽样审计——预筛阈值标定自旧素材,新风格首查必须全量比对一次防漏杀。可疑的脸用 `--frames <帧号> --face <脸序> --output face.png` 钻取原生分辨率单脸图裁决;眼部裁决要在眼部尺度放大后过五项:瞳孔近圆、虹膜有纹理、双眼 catchlight 一致、视线方向一致、眼形对称。职责边界与 ASR 一致:OC 只给几何与测量,质量裁决与阈值政策属于 Agent。
   - 量主体在画面里的位置:`oc media subject <absolute-path> [--every N] [--frames a,b,c] [--no-pose] --json`。不需要打开的 Project。内置人像分割(PPHumanSeg,5.9MB)给出主体的外接框与质心,**全部是画面百分比而不是像素**——候选图分辨率各不相同(1024×1536 / 1080×1920 / 800×1408),按像素比必然错。姿态模型(MediaPipe Pose,5.3MB)作为增强,给分割给不了的东西:肩、髋、腕、踝的关键点,以及肩→腕的**手臂角度**。**分工的理由是实测出来的**:姿态模型要"人形骨架",而飘逸裙摆会把腰髋腿全盖住、把人变成一个锥形,那时它直接检不出;分割没有这个前提,裙子本来就属于主体。反过来,姿态能回答"手臂还张着吗",而这是转场要接住"刚挥完"那个姿势时唯一能变成数的量。**字段语义有一条守死的线:`box` 是分割外接框、含拖尾衣料,它不是脚**——实拍段框底是鞋,仙侠段是裙尾,同一个数在两侧量的是不同东西;真正的脚只在 `pose.ankles`,且只在模型自己认为看得见时才输出(裙摆遮住脚踝时它给 0.13~0.34,如实报告"看不见")。精度边界:掩膜是 192×192 的,框的边一步就是 **0.52 个百分点**,再往下是量化噪声不是信号;质心不受此限(它是几万像素的均值)。**要那张掩膜本身**(做"文字被主体遮挡"这类排版)就加 `--output-mask <文件或目录>`:采样一帧写成那个文件,多帧当目录、按 `mask-<帧号>.png` 命名;默认按引擎内部的 192×192 二值原样给,`--mask-full-resolution` 放大到源分辨率(双线性,当遮挡蒙版更好用)。掩膜的外接框与返回的 `box` 出自同一次分割、必然一致——但 `width`/`height` 是两条边之差、不含端点那一格,自己量掩膜时要按同样定义算。**要拿掩膜去核对 `box` 就用默认的 192×192**(实测三帧逐格 0.00000 差):`--mask-full-resolution` 的双线性放大会把边缘晕开,阈值一切,右边和下边各外扩约一格(实测 0.42~0.47 个百分点,左/上因为放大左上对齐而不偏)——它是给遮挡用的软边蒙版,不是量化基准。
   - 挑出对得最齐的那一张:`oc media align <reference> <candidate...> [--no-pose] --json`。逐个候选给出相对基准的**带符号百分点差**,按最差项升序排,测不到主体的沉底。**排序只用 `boxTop` 和 `centroidX` 两项**,因为只有它们在换装后仍量的是同一个东西——`boxHeight` 与 `centroidY` 都被拖尾衣料系统性拉长(两侧差 2~3 个百分点是布料造成的,不是没对齐),把它们算进排序等于按裙子长度扣分;它们仍然输出,但只作参考。手臂角度差会**同时试两种左右配对取较优**:背影没有正脸定向,模型对"哪只是左手"的判定在两帧之间会翻转,实测同一姿态按下标直比是 72°、换配对是 22°。**画幅不同会结构化失败**而不是偷偷居中裁齐后再比——百分比只在同画幅之间可比,悄悄裁齐会变成三个月后没人说得清为什么数不对的坑。阈值不在这条命令里:它只出数和排序,"多少算过"是政策,属于 Agent;而且**不要直接沿用别处量出来的容差**,mask 质心包含伸出的手臂与飘起的披帛,和只量头发得到的数不是一个口径,要在这个指标上自己标定。
   - 直接导入 ASR 或字幕转写:`oc caption import-srt --file transcript.srt --font-asset-id <font-asset-id> --json`。cue 时间戳按 Sequence 自己的精确帧率换算,所以 30000/1001 的 Project 不会在末尾差出整帧。用 `--offset-frames <frames>` 整体平移(负值提前)。cue 编号、CRLF、BOM、WebVTT 的 `.` 小数和折行的 cue 文本都被接受;cue 自己的换行折叠成空格,因为换行由样式决定。重叠一两帧的 cue 会被修剪到首尾相接,而不是让导入失败;无法解析的时间行会点名所在块失败。它走与 `caption add-batch` 相同的单样式原子批。
   - 只更新给出的 Caption 字段:`oc caption update <caption-id> --text "新文字" --end-frame <exclusive-frame> --color "#RRGGBBAA" --rotation -8 --scale-percent 125 --json`。省略的内容、区间和样式字段保持不变;`--no-underline` 显式关闭下划线。改 `--text` 时,逐字高亮的 tokens **只要还能按序拼回新文本就保留**(只动空白/标点的编辑不丢高亮);拼不回才清空,且响应里的 `droppedTokens`/`droppedEmphases` 会如实报告丢了什么——看到它就意味着这条字幕的逐字高亮没了,需要重挂 tokens(协议的 update 接受 `tokens` 字段整组替换)或接受平铺。`--clear-tokens` 显式清掉逐字时间。
   - 把一条 Caption 移到另一条 Caption Track 和/或精确起始帧:`oc caption move <caption-id> --to-track <track-id> [--to-frame <frame>] --json`。
   - 移除一条定时 Caption:`oc caption remove <caption-id> --json`。它的私有样式 Component 在同一事务里移除;共享样式保留。
   - 列出可编辑的文字贴纸:`oc sticker list --json`。
   - 按精确帧添加文字贴纸:`oc sticker add "重点来了" --at-frame <frame> --duration-frames <frames> --font-asset-id <font-asset-id> --preset highlight --json`。preset 有 `highlight|variety|fresh|alert|tech|mono`;样式、位置和出入场动画 flag 仍可独立编辑。入场和出场都接受 `none|fade|pop|bounce|zoom|slide_up|slide_down|slide_left|slide_right`;用 `--enter-frames` 和 `--exit-frames` 设定各自精确的本地帧时长。返回的 `data.layout` 是这张贴纸的占位检查,`warningCount > 0` 就当场改位(见「检查各层在画面上不打架」)。preset 派生的字号按画布**短边**取基准,横竖屏同一个数;文案超过 86% 画宽时先把字号、描边、阴影、底板内边距**整套按同一比例**收到最多 85%,再装不下就在最接近中点的可断处折成两行(返回体里的 `text` 会带 `\n`),不会把字压成一条粗边小字。显式给了 `--font-size` 的贴纸不经过这一步;点名了 `--outline-width`/`--shadow-y` 这类字段的,该字段照你给的数。**preset 的默认字号是按手机观看定的,`--font-size` 用来放大(封面主标题、全屏卡),不要往下压**——想要更小的字通常意味着该缩短文案或折行;成片里贴纸偏小是用户最常抱怨的观感问题之一。
   - 只更新给出的贴纸字段:`oc sticker update <clip-id> --text "新的重点" --preset tech --x <pixels> --enter slide_left --json`。`--preset` 只换整套**看相**(字体、颜色、描边、动画),**不动你已经摆好的位置/缩放/旋转/透明度**;想连排位一起回到 preset 的种子,显式加 `--reset-placement`。显式 flag 在 preset 之后应用;省略的字段保持不变。
   - 移除一个文字贴纸:`oc sticker remove <clip-id> --json`。只移除贴纸 Clip 及其私有 Component;绝不编辑或移除音频。
   - 列出本构建提供的所有文字贴纸 preset:`oc sticker presets --json`。集合来自服务,所以它就是 `--preset` 会接受的集合;点名一个它不认识的,会带着完整列表失败,而不是悄悄替换成默认值。
   - 移除一个不再被使用的项目 asset:`oc asset remove <asset-id> --json`。只要还有 Clip 或 Component 引用它,OrangeCut 就会拒绝并点名引用方,因此不会留下一个校验通过却渲染不出的 Project。
   - 列出可编辑的形状图层:`oc shape list --json`。
   - 按精确帧添加形状:`oc shape add rectangle --at-frame <frame> --duration-frames <frames> --json`。种类有 `rectangle|square|ellipse|circle|triangle`;可选的几何、填充、描边、阴影、位置、缩放、旋转与不透明度 flag 仍可独立编辑。
   - 只更新给出的形状字段:`oc shape update <clip-id> --kind circle --width 320 --fill-color "#42D6C5D9" --x <pixels> --json`。circle 和 square 保持等边;省略的生命周期、几何、外观与位置字段保持不变。
   - 移除一个形状:`oc shape remove <clip-id> --json`。只移除形状 Clip 及其私有 Component;绝不编辑或移除音视频 Clip。
   - 标记、箭头和目标聚焦默认不带音效，保留素材原声。需要音效时导入用户选择的音频，在时间线上单独添加。旧版本组件提示音可用 `oc sfx marker <clip-id> --preset none --json` 清理，旧工程总开关兼容 `oc sfx markers --no-enabled --json`；兼容契约见 [references/marker-sound.md](marker-sound.md)。
   - 在贴纸起点加独立音效:从 `oc sticker list --json` 读出该贴纸精确的 `startFrame`,用 `oc asset import <absolute-audio-path> --json` 导入已授权的音频,再单独提交一次 `oc timeline add <audio-asset-id> --at-frame <startFrame> --json`。每次变更用一对新的 revision/idempotency-key。绝不把贴纸创建/更新与音频放置合进一个 CommandBatch,也绝不虚构贴纸-音频链接或分组。
   - 当文字、贴纸、形状和字幕表达不了时,把你自己的 DOM 放上时间线——信息卡、表格、内联 SVG、CSS 动画覆盖层:读 [references/html-component.md](html-component.md),通过 `oc command apply` 提交 `dev.orangecut.html` 组件(需要先审阅时用 `oc proposal create`)。动画用作用域内的 CSS `@keyframes`;script、远程引用和裸 `src` 值会被拒绝。
   - 提交显式的 Core CommandBatch:读 [references/request-contract.md](request-contract.md),写一个常规的(非 linked、非特殊)临时严格 JSON 请求(无重复对象名、无 `NaN`/`Infinity`、无过深嵌套),然后运行 `oc command apply --file <request.json> --json`。
   - 只校验不提交原始 Batch:给 `oc command apply` 加 `--dry-run`。
   - 提出一个或多个可审阅的变更而不改动 Project 真相:读 [references/proposal-contract.md](proposal-contract.md),按同样规则写一个临时严格 proposal JSON,然后运行 `oc proposal create --file <proposal.json> --json`。
   - 把当前 Sequence 导出到用户授权的绝对路径:`oc export start --output <absolute-path.mp4> --preset publish --json`。加 `--fps/--crf/--bitrate-kbps`,以 Sequence 未按其创作的帧率或质量交付。给手机传预览用 `--preset preview`(compact 速度 + 高 crf,竖屏一分钟稳在 ~20MB 内,省掉外部 ffmpeg 二压)。保留返回的不透明 `jobId`;绝不推断或暴露渲染器路径。
  加 `--from-frame`/`--to-frame` 只导出一个半开的帧窗口——
  两者都省略保持历史性的全 Sequence 导出;迭代一段
  就只花一段的钱。
4. 变更之后,重新读时间线并核对返回的 revision 与状态。绝不凭进程退出码宣称成功。
5. 只有当用户明确要求回退或重放历史时,才用 `oc undo --intent "..." --json` 或 `oc redo --intent "..." --json`。清空时间线是一次新的语义编辑,绝不是反复 undo。历史重试必须保持原操作与重试身份;绝不因为响应不确定就发起一次全新的 undo/redo。

对于响应可能需要网络恢复的 Asset import、timeline、keyframe、caption、audio、文字贴纸或 shape 的写入、undo 或 redo:先读快照 revision,并在首次调用前选好一个紧凑的唯一 key。给 `asset import`、`timeline add/split/move/trim/speed/remove/clear`、`keyframe upsert/remove/clear`、`caption add/add-batch/import-srt/update/remove`、`audio volume`、`sticker add/update/remove`、`shape add/update/remove`、`undo` 或 `redo` 同时传 `--base-revision <revision>` 与 `--idempotency-key <key>`;CLI 拒绝只传其中一个。结果不确定时,用两个值都不变的完全相同命令重试。OrangeCut 返回其已持久化的事务,不产生另一份副本、历史移动、revision 或 Event。import 重放使用已核验的项目自有媒体,而非原始路径。key 复用时若操作、路径、种类、base、intent 或编辑参数有变,以 `IDEMPOTENCY_CONFLICT` 失败。

Project 创建时还没有 Project revision,所以它的恢复身份是精确模板加 `--idempotency-key`。key 会被单向哈希成应用私有的 Project ID,绝不以明文出现在 Project 真相里。复用它却改了标题、画幅比或帧率,以 `IDEMPOTENCY_CONFLICT` 失败。

科技感文字、目标标注、原始录屏后期、通用媒体窗口，以及 `oc html visual <magnify|wipe|window|layers|markup> <config.json>` 的局部放大、前后对照、桌面窗口、分层文字和描绘批注，见 [references/visual-composition.md](visual-composition.md)。先使用这些跨作品能力，单期流程或状态卡继续在作品内编写 HTML。批注固定在源像素坐标；页面滚动或镜头运动应切段检查。分层复用已有抠图，透明主体需与原画面对齐。

设备展示使用 `oc html device <config.json> --json`：将已导入录屏嵌入透明手机机身，叠在普通视频上，保持源比例。支持 silver/black、front/left/right、位置、高度和阴影；开孔默认 none。Desktop：组件 → 设备展示，可重新打开改外观或替换录屏。支持 `--dry-run` 和完整重试身份；参数见上述共享编排参考。

目标聚焦使用 `oc html focus <config.json>`：区域用柔边蒙版压暗周围；对象复用透明 PNG/WebM，或先 `oc media focus-cutout` 根据源像素提示框制备轮廓。后者返回可查询、可取消的媒体任务，不修改 Project；实际检查空目标帧、边缘与对齐后再正常导入和添加。源画面与主体静音，原声独立保留一次。参数、尺寸和边界见上述共享编排参考。

双画面使用 `oc html dual <config.json> --json`，配置两路已导入的 Asset、各自源入点、时长、适配和窗口位置；先加 `--dry-run` 可只验证。整个编排通过一个可撤销的 CommandBatch 提交。精确重试必须同时复用原来的 `--base-revision` 与 `--idempotency-key`，不得把 revision 改成当前值；后续新增无关轨道不会重复创建窗口。
